## 1. 项目概览

**定位**：面向**个人求职者**的本地桌面工具 —— 多招聘网站岗位采集 + 半自动简历投递 + AI 辅助。

**技术栈**（真实环境实测）：
| 项 | 值 |
|---|---|
| 语言 | Python 3.14（Windows） |
| GUI | PySide6 6.11.1（Qt6，7 页签桌面应用） |
| 浏览器自动化 | playwright 1.58（chromium 145，headless/headed 双模式） |
| 存储 | SQLite 单文件（`data/app.db`，WAL，8 表 + 2 个迁移） |
| 调度 | APScheduler 3.11（每日增量采集） |
| LLM | openai 兼容 SDK（任意 Base URL：DeepSeek/通义/Ollama 等） |
| 其他 | httpx / pypdf / python-docx / requests |

**五大能力**：
1. 5 站点岗位采集：51job、智联（zhaopin）、拉勾（lagou）、猎聘（liepin）、Boss直聘（zhipin）
2. 登录管理：扫码登录、短信登录、**手动登录**（打开浏览器用户自己登录后关窗，程序验证）
3. 半自动投递：程序完成机械操作，最终提交由用户确认（风控：每日上限/随机间隔/时间窗）
4. 多简历版本管理（PDF/Word 解析）
5. AI 功能 9 项：简历优化/匹配评分/招呼语/投递策略/岗位推荐/跟进话术/面试预测/薪资分析/周报

## 3. 架构与数据流

```
PySide6 GUI(7页签)
   │ AsyncWorker(QThread + asyncio.run)     ← GUI 不直接 await，跨线程经 Qt 信号
   ▼
Services（Auth/Crawl/Apply/Ai/Resume/Registry）
   │ 全部 async；依赖方法内延迟导入+try/except（模块缺失不崩溃）
   ▼
Collectors（每站一个类，实现 Collector ABC）+ BrowserManager（Playwright 持久化上下文）
   ▼
SQLite（app/db/repository.py 纯函数 CRUD）
```

**核心数据流**：
- 登录：`LoginCenterPage` → `AuthService.login/manual_login` → `BrowserManager`（user_data_dir 落盘 Cookie）→ 状态回调 → 状态灯
- 采集：`SearchPage` → `CrawlService.run_all_enabled` → `BrowserManager.get(site)` + `Collector.search_jobs` → `repository.upsert_job`（(source,job_id) 去重）
- 投递：`ApplyPage` → `ApplyService.apply_job` → 风控检查 → `Collector.open_apply/submit_apply` → 确认回调（GUI 模态框）→ 投递记录入库
- AI：`AiService.chat`（openai 兼容，asyncio.to_thread）→ 提示词模板（DB prompts 表，可编辑）

## 4. 关键接口契约（改代码前必读）

> 这些签名是模块间集成契约，其他代码按此调用。**改动签名 = 破坏集成**，请同步更新所有调用方。

### 4.1 Collector 抽象（app/collectors/base.py）
```python
class Collector(ABC):
    source: str                      # 站点标识：51job/zhaopin/lagou/liepin/zhipin
    COMMON_LOGIN_COOKIES: frozenset  # 通用登录特征 cookie 名（精确匹配）
    async def _cookie_logged_in(self, page, extra_names=None) -> bool   # cookie 辅助判定
    # 以下 9 个为抽象方法（全部 async）：
    async def goto_login(self, page) -> None
    async def is_logged_in(self, page) -> bool          # 见 §6 保守判定原则
    async def login_qr(self, page, qr_callback) -> bool
    async def login_sms(self, page, phone: str, code: str) -> bool
    async def search_jobs(self, page, keyword: str, city: str | None, max_pages: int = 3) -> list[RawJob]
    async def parse_job(self, page, job_url: str) -> RawJob | None
    async def open_apply(self, page, job) -> None
    async def submit_apply(self, page, resume_name: str) -> bool
    async def send_greeting(self, page, job, text: str) -> bool   # Boss 专用（发消息）
```

**RawJob 字段**（与 jobs 表一一对应）：`source, job_id, title, company, company_size, industry, salary_min, salary_max, salary_raw, city, district, experience, education, tags(list), description, publish_date, job_url, crawl_time, status, is_favorite, match_score`。含 `to_job()` 转 DB 模型。

**SITES**：`{'51job':'前程无忧','zhaopin':'智联招聘','lagou':'拉勾网','liepin':'猎聘','zhipin':'Boss直聘'}`

### 4.2 BrowserManager（app/browser/driver.py）
```python
BrowserManager.get(site: str, headless: bool = False, channel: str | None = None) -> BrowserManager
# 缓存键=(site, headless, channel)；channel=None=chromium，"msedge"=系统真实 Edge
# 强风控站点（SITE_USE_REAL_BROWSER={"zhipin"}）且系统存在 Edge（EDGE_EXE 探测）时自动用 "msedge"
async start() / stop() / new_page() / close_all_pages()
async wait_for(page, selector, timeout_ms=30000) / wait_for_url_contains(page, part, timeout_ms)
async sleep(ms) / screenshot_element(page, selector, path) / save_cookies_backup(path)
```
- **user_data_dir = data/browser/<site>/**，Cookie/localStorage 自动落盘持久化
- start() 内置**反自动化检测**：移除 `--enable-automation`、注入 STEALTH_INIT_SCRIPT（删除 webdriver、伪造 window.chrome/languages/plugins）
- **Boss 直聘用真实 Edge（channel="msedge"）**，对抗强风控（Playwright chromium 会触发页面反复刷新/无法扫码）
- stop() 对已关闭 context 用 `is_closed()` 判断，避免挂起

**⚠️ 重要**：Boss 用 Edge profile（data/browser/zhipin 是 Edge 的 profile），与其他站点的 chromium profile 不通用；切换后需重新扫码登录 Boss。

### 4.4 数据层（app/db/）
- `get_connection()` 在 **app.db.database**（不在 repository！历史上踩坑，见 §9.4）
- repository 全部为**纯函数，首参 conn，不提交事务**；调用方用 `with get_connection() as conn:`（自动 commit/rollback/close）
- `init_db()`：建表 + user_version 迁移（当前 v2）+ seed 默认数据（9 条提示词 + 8 项默认 settings）
- `get_setting(conn, key, default=None)` / `set_setting(conn, key, value)`（settings 表可覆盖代码内常量，见 settings.py 的 get_setting_override）
- 模型 list 字段（SearchTask.sites/keywords/cities、Job.tags）在 Python 侧是 **list 类型**，as_dict() 序列化为 JSON 字符串

### 4.5 GUI 桥（app/ui/worker.py）
```python
AsyncWorker.run_async(coro_factory, on_success=None, on_failure=None, on_progress=None)
# coro_factory 是无参返回 coroutine 的函数；回调在 Qt 主线程执行（信号 QueuedConnection）
# 异步任务一律经此运行，禁止在 GUI 线程直接 await
```

## 6. 开发约定（严格遵守）

1. **全部 async**：服务/采集器/BrowserManager 都是 async（Playwright 生态）；GUI 经 AsyncWorker 运行
2. **延迟导入容错**：模块间依赖在方法内 `from x import y` + `try/except ImportError`，返回安全默认值（[]/False/None），模块缺失绝不崩溃
3. **is_logged_in 保守判定（核心安全原则）**：
   - **无任何已登录证据 = 未登录**（宁可误报未登录，绝不误报已登录）
   - 已登录证据 = **结构化 DOM 选择器**（href 特征/class）+ **登录特征 Cookie**
   - ⚠️ 禁止用宽泛文本选择器（`text=个人中心`、`text=退出`）——未登录页面也常见，曾致"没扫码就报登录成功"
   - ⚠️ Cookie 判定必须**精确名匹配**且只收"登录后才有"的 cookie（51job 实测：`uid` 是匿名统计标识，`51job` 才是登录 cookie——匿名探测会种 uid！）
4. **浏览器用完必须 stop()**：释放 user_data_dir 的 profile 锁，否则下次 launch_persistent_context 冲突（chrome exit 21）
5. **事务提交**：repository 不自动提交；`with get_connection() as conn:` 或显式 `conn.commit()`
6. **Playwright locator 方法全是 async**（count/text_content/get_attribute/click...），必须在 async 函数里 await；同步辅助函数只做字符串/正则
7. **bat 文件**：UTF-8 + **CRLF** + `chcp 65001`（LF 会被 cmd 解析错乱；中文必须有 chcp）
8. **新增站点**：`app/collectors/<site>.py` 实现 Collector → `app/services/registry.py` COLLECTOR_MODULES 登记 → 若需状态灯，SITES 已含
9. **UI 线程**：worker 线程内绝不直接操作 QWidget，一律经 Qt 信号转发主线程
10. **LLM 功能**：未配置时抛 RuntimeError（"未配置大模型 API..."），GUI 捕获提示；AI 只给建议，不代执行投递

## 9. 踩坑记录（历史 bug 与教训 —— 最值得读的部分）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 9.1 | 采集后浏览器进程残留，再次操作 exit 21 | CrawlService 只 close_all_pages 不 stop()，profile 锁被占 | 站点收尾补 `browser.stop()` |
| 9.2 | chromium 下载卡死 30+ 分钟 | playwright 官方 CDN（dbazure→microsoft）在此网络不可用 | 定位真实 URL（chrome-for-testing-public）+ npmmirror 镜像手动安装 |
| 9.3 | `locator.count()` 永不匹配 | **Playwright locator 方法全异步**，同步辅助函数里 `loc.count()` 未 await，抛 "coroutine never awaited" 且被 try/except 吞掉 | `_match`/`_first` 改 async + 全部调用点 await（3 采集器约 100 处） |
| 9.4 | 投递计数恒为 2^40（拒绝一切投递） | `_lazy("app.db.repository", "get_connection")` —— get_connection 在 **app.db.database** | 改为正确模块 |
| 9.5 | 投递记录写不入库 | repository 不提交事务，`_record_application` 缺 conn.commit() | 补 commit |
| 9.6 | 投递记录 NOT NULL 报错 | schema v1 `job_ref_id NOT NULL` 与设计"找不到仍插入"矛盾 | v2 迁移重建表（可空 + 唯一索引）；repository 补 `get_job_by_source_id` |
| 9.7 | **没扫码就报"登录成功"**（3 轮修复） | is_logged_in 兜底 `return True`（找不到证据=默认已登录）；未登录首页不重定向、无登录表单元素 | ①兜底改 False ②移除 text= 宽泛选择器 ③用真实会话实测校准（href 特征 + cookie） |
| 9.8 | 已登录但显示"登录中" | ①启动状态检查串行 33s ②DOM 选择器匹配不到真实已登录页面（51job 无 .username 类） | ①并行化（Semaphore 3）②真实会话 dump DOM 校准 + 登录 cookie 判定（`51job` cookie，非 uid）③GUI 35s 超时兜底 |
| 9.9 | Boss 扫码页面闪来闪去 | chromium 带 `--enable-automation`/`navigator.webdriver` 被风控识别 | 移除自动化标志 + 注入反检测脚本 |
| 9.10 | 手动登录验证挂起 120s+ | 用户关闭浏览器后，对已关闭 context/page 再操作（stop 内 context.close）与关闭主流程死锁 | `is_closed()` 判断跳过 + 清理只停 driver + wait_for 超时保护 |
| 9.11 | 51job 登录判定反了 | 匿名访问也种 `uid` cookie（统计标识），登录才有 `51job` cookie（536B） | 登录判定只认 `51job` cookie；通用集合只收 uid/userid 等"登录才有"的 |
| 9.12 | bat 中文乱码/解析错乱 | UTF-8 无 BOM + LF 行尾；cmd 需要 CRLF + 匹配的代码页 | UTF-8 + CRLF + `chcp 65001`（GBK 方案在 UTF-8 控制台会乱） |
| 9.13 | **Boss 扫码页面始终刷新，无法扫码**（基础反检测不够） | Playwright 自带 chromium 携带 CDP 调试通道 + automation 痕迹，Boss 强风控识别后触发页面反复刷新 | ①Boss 改用系统**真实 Edge**（`channel="msedge"`，`SITE_USE_REAL_BROWSER={"zhipin"}`）②反检测增强（删除 webdriver + 伪造 window.chrome/languages/plugins）③提供"手动登录"兜底。**注：Edge 通道效果需用户实测确认**，若仍被检测则需升级为 connectOverCDP 连接用户日常浏览器 |

## 10. 已知限制与待办（续开发方向）

### 已实现 ✅
- P1 骨架 / P2 采集闭环 / P3 增量调度 / P4 半自动投递 / P5 五站采集器 / P6 简历+AI / P7 全量接线 / P8 大部分（测试+README+健壮性）
- 登录：扫码、短信、**手动登录**；51job 登录判定已真实校准
- **Boss 直聘改用真实 Edge 浏览器**（对抗强风控）+ 反检测增强（stealth 脚本）

### 待办 / 建议优先级
1. **【当前最急】Boss 扫码登录待用户实测确认**（进行中）：Edge 通道 + 反检测已实现并本地验证（webdriver=None、chrome 伪装、Edge 启动正常），但**能否稳定扫码需用户在真实环境确认**。若 Edge 里仍反复刷新 → 升级方案：connectOverCDP 连接用户日常浏览器（360 极速/Chrome），或引入 playwright-stealth
2. **其他 4 站登录判定真实校准**（高）：51job 已用真实会话校准；智联/拉勾/猎聘/Boss 的 SEL_USER_MENU 与登录 cookie 名是"通用猜测"，登录后可能判不准。方法：让用户登录某站 → dump 真实 DOM + 真实 cookie 差异 → 更新该站选择器与 `SEL_LOGIN_COOKIES`/`extra_names`
3. **全自动投递模式**（中）：apply_page 的"全自动"开关已存在但只弹风险提示不生效；实现需在 ApplyService 加自动确认路径（保留风控硬限制）
4. **每日采集时间修改即时生效**（低）：search_page 修改 daily_crawl_time 后需重启应用（SchedulerService 启动时读常量）
5. **PyInstaller 打包**（低）：PySide6+Playwright 打包体积大（chromium ~300MB），Python 3.14 兼容性未验证；如需分发再处理
6. **站点改版维护**：每个采集器顶部有"选择器常量区"，改版时优先在此调整；Boss/猎聘风控最强，需降频采集
7. **真实站点全量验证**：需用户登录后跑一次真实采集（51job 曾实测：无登录返回空属预期，登录后应可采）

### 已知限制
- 简历信息采集**不做**（合规：个人信息保护法；只投递用户自己的简历）
- 全自动高频投递有封号风险，默认半自动 + 风控硬限制
- 启动时登录状态检查约 10s（并行 5 站 headless）；35s 超时兜底

## 12. 一句话总结给接手者

> 这是一个**可运行、已验证**的 Python 桌面应用：5 站采集 + 半自动投递 + AI 辅助，SQLite 全本地。代码质量的关键在三个原则：**异步一致**（Playwright 全 async）、**保守判定**（登录态无证据即未登录）、**健壮容错**（延迟导入 + 浏览器资源必释放）。续开发最优先的事项是**其余 4 站登录判定的真实会话校准**（§10-1），其余按待办清单推进。测试套件（§8）是回归底线，改完必跑。
